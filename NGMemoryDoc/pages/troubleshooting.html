Troubleshooting

Typische Fehlerquellen bei Handles, Control-IDs, Speicherzugriff, Pattern-Scans, Capture Protection, Overlays und DPI.

Common failure points around handles, control IDs, memory access, pattern scans, capture protection, overlays, and DPI.

IntPtr.Zero beim FensterfindenIntPtr.Zero when finding a window
  • Process name should not include .exe.
  • The process must already be running.
  • Some apps have no MainWindowHandle; enumerate windows with EasyGuiInterop.EnumerateProcessWindowHandles.
  • Try partial title search with EasyWindow.Find("notepad", "Untitled").
Control-ID funktioniert nichtControl ID does not work

Classic helpers nutzen Win32-Control-IDs. Browserbasierte, owner-drawn oder moderne Framework-UIs können diese IDs verstecken oder anders abbilden.

Classic helpers use Win32 control IDs. Browser-based, owner-drawn, or modern framework UIs can hide or remap those IDs.

Memory Read/Write fails
  • Run as administrator.
  • Match x86/x64 architecture.
  • Make sure the address is valid for the current process instance.
  • Use Scanner or module base + offsets instead of hard-coded absolute addresses.
Pattern scan finds nothing
  • Verify process name and pattern bytes.
  • Use wildcards for relocatable bytes: ??.
  • Search a broader range.
  • Confirm that the module is loaded.
SetWindowDisplayAffinity returns false
  • HWND is not a top-level window.
  • HWND belongs to another process.
  • Windows version does not support the requested mode.
  • The window has not created its handle yet.
Capture-Maske wird nicht schwarzCapture mask does not show black
  • Use effect Black.
  • Keep capture protection enabled.
  • Use opacity 0 for nearly invisible on-screen masking.
  • Some capture methods ignore display affinity.
DPI position looks wrong

Enable DPI awareness in the application before showing forms. For best results, use PerMonitorV2 DPI awareness in app config or manifest.
