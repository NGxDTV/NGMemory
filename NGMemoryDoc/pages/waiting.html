NGMemory.Waiting + NGMemory.Easy

Waiting & Actions

Warte gezielt auf Bedingungen, Werte, Fenster, Controls, Fensterzustände, Prozesse, Signale oder die sichtbare Wirkung einer Aktion. Alle Polling-Methoden unterstützen Zeitlimit und Abbruch; für WinForms stehen asynchrone Varianten bereit.

Wait for conditions, values, windows, controls, window states, processes, signals, or the observable effect of an action. Every polling method supports timeouts and cancellation, with asynchronous variants for WinForms.

EasyWait liefert bewusst einfache Werte wie bool, IntPtr oder Prozess-ID. Waiter liefert zusätzlich Ergebnisstatus, Laufzeit, Prüfversuche und die letzte Exception. EasyWait intentionally returns simple values such as bool, IntPtr, or a process ID. Waiter also returns outcome, elapsed time, probe count, and the last exception.

EinbauSetup

Für die kompakte API genügt NGMemory.Easy. Die Kern-API wird über NGMemory.Waiting eingebunden. Es sind keine zusätzlichen Pakete nötig.

Use NGMemory.Easy for the compact API and NGMemory.Waiting for detailed results. No additional packages are required.

C# · Namespaces
using System;
using System.Threading;
using System.Threading.Tasks;
using NGMemory.Easy;
using NGMemory.Waiting;

EasyWait

Ideal für kurze Automationsabläufe. Ein Timeout wird als false, IntPtr.Zero oder 0 zurückgegeben.

Best for short automation flows. A timeout returns false, IntPtr.Zero, or 0.

Waiter

Ideal für Bibliothekscode, Logging und Fehlerdiagnose. WaitResult unterscheidet Timeout, Abbruch, Fehler und ausgeschöpfte Wiederholungen.

Best for library code, logging, and diagnostics. WaitResult distinguishes timeout, cancellation, failure, and exhausted retries.

Easy: Auf Fenster wartenEasy: Wait for a window

ForWindow prüft sofort und danach im angegebenen Intervall. Der Prozessname funktioniert mit oder ohne .exe; der Titel ist optional und wird als Teiltext ohne Beachtung der Groß-/Kleinschreibung gesucht.

ForWindow probes immediately and then at the requested interval. The process name works with or without .exe; the title is optional and matched as a case-insensitive substring.

C# · Easy window template
IntPtr window = EasyWait.ForWindow(
    processName: "notepad",
    partialTitle: "Notes",
    timeout: 15000,
    checkInterval: 100);

if (window == IntPtr.Zero)
{
    Console.WriteLine("Window did not appear within 15 seconds.");
    return;
}

EasyWindow.FocusWindow(window);
Wirkung: Der Code läuft erst weiter, wenn ein passendes Fenster existiert. Es gibt keine starre Pause, die auf schnellen Systemen Zeit verschwendet oder auf langsamen Systemen zu kurz ist.Effect: Execution continues only after a matching window exists. There is no fixed delay that wastes time on fast systems or fails on slow ones.

Kindfenster und Control-IDChild window and control ID

C# · Child and control template
IntPtr dialog = EasyWait.ForChildWindow(window, "Settings", timeout: 5000);
IntPtr saveButton = EasyWait.ForControl(dialog, controlId: 1001, timeout: 5000);

if (dialog == IntPtr.Zero || saveButton == IntPtr.Zero)
    return;

Easy: FensterzuständeEasy: Window states

ForWindowVisible

Wartet, bis das Handle weiterhin gültig und das Fenster sichtbar ist.

Waits until the handle is still valid and the window is visible.

ForWindowEnabled

Wartet, bis das Fenster Benutzereingaben akzeptieren kann.

Waits until the window can accept user input.

ForForegroundWindow

Wartet, bis genau dieses Fenster im Vordergrund liegt.

Waits until this exact window is in the foreground.

ForWindowClosed

Wartet, bis das Fensterhandle ungültig geworden ist.

Waits until the window handle is no longer valid.

C# · State workflow
IntPtr dialog = EasyWait.ForWindow("myapp", "Export");
if (dialog == IntPtr.Zero)
    return;

EasyWait.ForWindowVisible(dialog, timeout: 3000);
EasyWindow.FocusWindow(dialog);

if (EasyWait.ForForegroundWindow(dialog, timeout: 2000))
    EasyKeyboard.TypeText("report.csv");

bool closed = EasyWait.ForWindowClosed(dialog, timeout: 30000);

Easy: Aktion ausführen und auf Wirkung wartenEasy: Perform an action and wait for its effect

DoAndWait führt die Aktion genau einmal aus. Anschließend wird die Abschlussbedingung geprüft, bis sie erfüllt ist, das Zeitlimit abläuft oder abgebrochen wird.

DoAndWait executes the action exactly once. It then polls the completion condition until it succeeds, times out, or is cancelled.

C# · Action template
bool saved = EasyWait.DoAndWait(
    action: () => EasyButton.Click(dialog, controlId: 1001),
    completionCondition: () =>
        EasyTextBox.GetText(dialog, controlId: 2001) == "Saved",
    timeout: 10000,
    checkInterval: 100);

if (!saved)
    Console.WriteLine("The save action had no visible success state.");
Wichtig: Das Zeitlimit beginnt, nachdem die Aktion zurückgekehrt ist. Eine blockierende Aktion kann von NGMemory nicht sicher abgebrochen werden. Verwende für längere Aktionen DoAndWaitAsync und reiche den CancellationToken weiter.Important: The timeout begins after the action returns. NGMemory cannot safely interrupt a blocking action. Use DoAndWaitAsync for longer work and pass its CancellationToken through.

Retry

RetryUntilSuccess ist anders: Die Aktion selbst wird bis zur maximalen Anzahl erneut ausgeführt. Nutze das nur für wiederholbare, idempotente Aktionen.

RetryUntilSuccess is different: it repeats the action itself up to the maximum attempt count. Use it only for repeatable, idempotent actions.

C# · Retry template
bool sent = EasyWait.RetryUntilSuccess(
    action: () => EasyButton.Click(dialog, 1001),
    successCheck: () => EasyTextBox.GetText(dialog, 2001) == "Sent",
    maxAttempts: 3,
    delayBetweenAttempts: 500);

Core: Präzise FenstersucheCore: Precise window search

WindowQuery unterstützt Prozessname oder Prozess-ID, exakten/teilweisen Titelvergleich, Sichtbarkeit, Aktivierung und ein eigenes Handle-Prädikat.

WindowQuery supports a process name or process ID, exact/partial title matching, visibility, enabled state, and a custom handle predicate.

C# · Core window template
var options = new WaitOptions
{
    Timeout = TimeSpan.FromSeconds(15),
    PollInterval = TimeSpan.FromMilliseconds(75)
};

var query = new WindowQuery
{
    ProcessName = "notepad",
    Title = "Notes.txt - Notepad",
    TitleMatch = WindowTitleMatch.Exact,
    RequireVisible = true,
    RequireEnabled = true
};

WaitResult<IntPtr> result = Waiter.ForWindow(query, options);

if (result.Succeeded)
    Console.WriteLine($"Handle: {result.Value}; probes: {result.Attempts}");
else
    Console.WriteLine($"Outcome: {result.Outcome}; elapsed: {result.Elapsed}");

WaitOutcome

Succeeded

Die Bedingung oder der gesuchte Wert wurde erreicht.

The condition or requested value was reached.

TimedOut

Das Zeitlimit ist nach mindestens einer Prüfung abgelaufen.

The timeout elapsed after at least one probe.

Cancelled

Der übergebene CancellationToken wurde ausgelöst.

The supplied CancellationToken was cancelled.

Faulted / AttemptsExhausted

Eine Prüfung schlug fehl oder alle Wiederholungen wurden verbraucht.

A probe failed or every retry attempt was consumed.

Core: Bedingungen und WerteCore: Conditions and values

C# · Condition template
WaitResult ready = Waiter.Until(
    condition: () => EasyTextBox.GetText(dialog, 1001) == "Ready",
    options: new WaitOptions
    {
        Timeout = TimeSpan.FromSeconds(5),
        PollInterval = TimeSpan.FromMilliseconds(100)
    });

ready.ThrowIfFailed();
C# · Value template
WaitResult<string> status = Waiter.ForValue(
    valueProvider: () => EasyTextBox.GetText(dialog, 1001),
    accept: value => value == "Completed",
    options: new WaitOptions
    {
        Timeout = TimeSpan.FromSeconds(20),
        PollInterval = TimeSpan.FromMilliseconds(150),
        IgnoreTransientErrors = true
    });

Console.WriteLine(status.Value);       // Last observed value
Console.WriteLine(status.Error);       // Last transient error, if any
Console.WriteLine(status.Attempts);    // Number of probes
IgnoreTransientErrors sollte nur aktiviert werden, wenn ein Prüfzugriff vorübergehend scheitern darf, etwa während ein fremdes Fenster neu aufgebaut wird. Programmierfehler sollten nicht dauerhaft verschluckt werden.Enable IgnoreTransientErrors only when a probe may fail temporarily, for example while an external window is rebuilding. Do not use it to hide persistent programming errors.

Process

C#
int processId = EasyWait.ForProcess(
    "myapp.exe",
    timeout: 30000);

if (processId != 0)
    EasyWait.ForProcessExit(processId, timeout: 60000);

WaitHandle

C#
using (var signal = new ManualResetEvent(false))
{
    // Another thread or component calls signal.Set().
    bool received = EasyWait.ForSignal(signal, timeout: 5000);
}

ForSignal funktioniert mit allen WaitHandle-Typen, beispielsweise ManualResetEvent, AutoResetEvent oder Semaphore.

ForSignal works with every WaitHandle type, including ManualResetEvent, AutoResetEvent, and Semaphore.

Async & Cancellation

Verwende in WinForms-Eventhandlern vorzugsweise die asynchronen Varianten. So bleibt die Oberfläche reaktionsfähig. Der Token beendet das Polling zeitnah, ersetzt aber keinen kontrollierten Abbruch innerhalb einer eigenen Aktion.

Prefer asynchronous variants inside WinForms event handlers so the UI remains responsive. The token stops polling promptly, but it does not replace cooperative cancellation inside your own action.

C# · WinForms async template
private CancellationTokenSource _waitCancellation;

private async void connectButton_Click(object sender, EventArgs e)
{
    _waitCancellation?.Cancel();
    _waitCancellation = new CancellationTokenSource();

    IntPtr window = await EasyWait.ForWindowAsync(
        "myapp",
        partialTitle: "Login",
        timeout: 20000,
        checkInterval: 100,
        cancellationToken: _waitCancellation.Token);

    statusLabel.Text = window == IntPtr.Zero ? "Not found" : "Ready";
}

private void cancelButton_Click(object sender, EventArgs e)
{
    _waitCancellation?.Cancel();
}
Für bewusst unbegrenztes Warten setzt die Kern-API Timeout = Timeout.InfiniteTimeSpan. Kombiniere das immer mit einem CancellationToken.For deliberate infinite waits, set Timeout = Timeout.InfiniteTimeSpan in the core API. Always combine it with a CancellationToken.

Typische FehlerCommon mistakes

Starre PauseFixed delay

ForDuration(5000) beweist nicht, dass ein Fenster bereit ist. Warte auf den tatsächlichen Zustand.

ForDuration(5000) does not prove that a window is ready. Wait for the real state.

UI-Thread blockiertBlocked UI thread

Synchrone Waits blockieren den aufrufenden Thread. Verwende in Eventhandlern die Async-Variante.

Synchronous waits block the calling thread. Use the Async variant in event handlers.

Falscher FenstertitelWrong window title

Dynamische Titel ändern sich oft. Nutze einen stabilen Teiltext oder WindowQuery mit Prozess-ID und Prädikat.

Dynamic titles change often. Use a stable substring or a WindowQuery with process ID and predicate.

Doppelte AktionRepeated side effect

Nutze Retry nicht für Zahlungen, Löschvorgänge oder andere nicht-idempotente Aktionen.

Do not use Retry for payments, deletion, or other non-idempotent actions.
